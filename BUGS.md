| **BUG-011** | `HIGH` | UI / Library / Layout | `LibraryScreen.kt` used a dynamic overlay `Box` where `FilterRow` had no solid background, and books in `ShelfGrid` overlapped with the filter chips on initial composition. | **BUG-012** | `HIGH` | Network / Metadata | Aggressive global timeout `withTimeoutOrNull(4500)` in `MetadataRepository.kt` cancelled and discarded all results if any single provider (like OpenLibrary or Google Books HTTP 429) was slow. | **BUG-013** | `MEDIUM` | UI / Library / Bookshelf | `BookshelfRow` used `verticalAlignment = Alignment.Bottom`, causing books with 2-line titles (e.g., Harry Potter) to push their covers higher than 1-line title books, creating uneven cover heights and ragged baselines. | **BUG-015** | `HIGH` | Audiobooks / Navigation / Lifecycle | 1) Navigating back from Audiobooks to Library via Drawer was blocked due to `popUpTo(Routes.LIBRARY)` no-op on the root route. 2) Audiobooks and text books were mixed together on the main reading shelf. 3) `AudioPlayerService` did not implement `onTaskRemoved`, causing playback to persist when app was swiped from recents. 4) Premature closing of `ParcelFileDescriptor` caused `MediaPlayer` bad descriptor errors after restart; speed chips in `HeroAudioPlayerCard` pushed play controls off-screen. | **FIXED** | 1) In `ApriNavHost.kt`, used `navController.popBackStack(Routes.LIBRARY, inclusive = false)` with fallback to root for Drawer destination switches. 2) In `LibraryViewModel.kt`, strictly filtered `!it.format.isAudio` (regular books shelf now contains zero audiobooks, and Audiobooks screen contains only audiobooks). 3) Added `onTaskRemoved` in `AudioPlayerService.kt` to pause, save Room progress, and stop service cleanly on task removal. 4) Updated `AudiobookPlayerController` to use `mp.setDataSource(context, uri)` directly with Main dispatcher coordination and persistent descriptor guards; redesigned `HeroAudioPlayerCard` with centered controls row and dedicated speed chips row below. | **BUG-016** | `CRITICAL` | Audiobooks / Timecode & Playback | 1) When restoring playback after restart, `mp.seekTo()` ran asynchronously while `mp.start()` was called immediately, causing `startProgressTracking()` to read transient `currentPosition` ~1000ms (`00:01`) and overwrite the true saved timecode in Room DB. 2) For audiobooks picked from temporary SAF providers (Downloads/third-party), URI permissions were revoked on process restart, causing `MediaPlayer` to throw `SecurityException` and fail to play even from zero. | **FIXED** | 1) Rewrote `AudiobookPlayerController` with `prepareAsync()` and `OnSeekCompleteListener` synchronization: `play()` and progress tracking now start strictly AFTER seek to the saved timecode finishes. 2) Added fallback data source resolution (`file://`, `ParcelFileDescriptor(fd, 0, statSize)`, and `DocumentCache.materialize`); during import in `LibraryRepository`, any non-persistable SAF audio file is automatically materialized locally so audiobooks never lose permissions. 3) Updated `AudioPlayerSheet` slider to fallback to saved `locatorOffset` and `totalChars` if player state is idle. Verified with 58 unit tests and release builds. |
| **BUG-017** | `CRITICAL` | Audiobooks / Pause & Resume Lifecycle | Tapping play button after pause failed to resume playback due to a race condition where `mediaPlayer` reference was assigned before async preparation completed; subsequent taps invoked `mp.start()` in un-prepared state throwing `IllegalStateException` and locking `MediaPlayer` into Error state. Additionally, audio focus request denial blocked playback entirely, and list item cards displayed static progress ("Не начато") while loaded/playing. | **FIXED** | 1) In `AudiobookPlayerController`, introduced `isPreparing` and `preparingBookId` state locks, and guarded `mediaPlayer` assignment so it is only assigned after `onPrepared` callback. 2) Replaced broken restart logic with seamless `togglePlayPause()` in `HeroAudioPlayerCard` and `AudioBookItemCard` so pausing and resuming are instantaneous without reloading or error transitions. 3) Made audio focus failure non-fatal. 4) Bound list item cards to live player position and duration (`% • current / total`). 5) Renamed header title to "Аудиокниги". Verified with 58 unit tests and release builds. |
| **BUG-018** | `CRITICAL` | Audiobooks / Engine & Resume Architecture | Legacy `android.media.MediaPlayer` failed on modern Android devices (OnePlus 12 / Android 14) and emulators (LDPlayer): 1) `MediaPlayer` created on `Dispatchers.IO` had no `Looper`, causing event listeners (`onPrepared`, `onCompletion`) to silently fail or never dispatch; 2) Calling `playbackParams` on paused/prepared states threw unrecoverable native OpenSL errors; 3) Pause/Resume state-machine race conditions locked playback. | **FIXED** | Completely re-architected audiobook playback using industry-standard **Android Media3 (ExoPlayer 1.5.1)**: 1) Replaced `MediaPlayer` with `androidx.media3.exoplayer.ExoPlayer` on `Dispatchers.Main`; 2) Configured native speech audio attributes and automatic system audio focus (`handleAudioFocus = true`) and headphone disconnect handling (`handleAudioBecomingNoisy = true`); 3) Clean `Player.Listener` implementation with accurate state management (`STATE_READY`, `STATE_BUFFERING`, `STATE_ENDED`); 4) Smooth variable playback speed (`0.5x - 3.0x`) and instant, race-free pause/resume/seek; 5) Persistent Room DB progress syncing with 2-second throttling and instant pause save. Verified with 58 unit tests and full release build. |
| **BUG-019** | `HIGH` | UI / Library / Shared Transition Collision | When a book was in progress, `ContinueReadingCard` (hero card at the top) and `BookshelfBookItem` / `BookGridCard` (on the shelf below) both rendered simultaneously on `LibraryScreen` with identical `rememberSharedContentState(key = "cover-$bookId")`. Jetpack Compose `SharedTransitionScope` requires unique keys per rendered scene; duplicate keys caused the shared element manager to treat the shelf cover as an exiting clone and render it completely transparent/invisible. | **FIXED** | Removed colliding `sharedCover(book.id)` and `sharedKey("title-$book.id")` modifiers from `ContinueReadingCard` in `ShelfItems.kt`. The shelf item now retains its unique transition identity to `BookDetailsScreen`, and both the top hero card and the shelf item render their book covers simultaneously and flawlessly. | **BUG-020** | `CRITICAL` | TTS / Text-to-Speech / Initialization | In `TtsController.kt`, `ensureEngine()` instantiated `TextToSpeech(context, listenerInit, pkg)`, but in `listenerInit.onInit(status)`, the code evaluated `val currentEngine = engine`. Because Android `TextToSpeech` initializes asynchronously via IPC service binding, `engine` was still `null` when `onInit` fired. As a result, `setupEngineInstance()` and `pendingReady?.invoke()` were never called, leaving `engine` null forever and preventing `speak()` from ever executing on any book or language. | **FIXED** | Captured the `createdTts` instance in `ensureEngine()`, resolved `val currentEngine = createdTts ?: engine` in `onInit`, properly invoked chained pending callbacks, and added language resolution unit tests in `ReaderLogicTest.kt`. |

| **BUG-022** | `HIGH` | Import / SAF File Picker / Comics | `LibraryScreen.kt`'s `SUPPORTED_MIME_TYPES` (passed to the system file picker via `EXTRA_MIME_TYPES`) listed invented MIME strings for CBZ/CBR (`application/vnd.comicbook+zip`, `application/vnd.comicbook-rar`) that no real Android `DocumentsProvider` reports for these extensions. | **BUG-023** | `HIGH` | Comics / CBR / Concurrency | `CbrDocument.openPage()` called `archive.getInputStream(header)` on a single shared `junrar.Archive` instance with no synchronization. `PagedReader.kt`'s `HorizontalPager`/`VerticalPager` (`beyondViewportPageCount = 1`) decodes the current page and both neighbors concurrently, each on its own IO-dispatcher coroutine — so `CbrDocument.openPage()` for different indices could run on different threads at the same time. junrar's `Archive` keeps mutable decompressor state that is not safe for concurrent `getInputStream()` calls; concurrent access corrupted it, decoding some pages to 0 bytes (visible in the UI as "не удалось загрузить страницу N" on some pages while neighbors rendered fine). Confirmed with a 4-thread concurrent read test against a real user CBR file (page 0 → 0 bytes without the fix). `CbzDocument`/`ZipArchive` were unaffected — their underlying `RandomAccessSource.readAt()` implementations are already `@Synchronized`. | **FIXED** | Wrapped the read in `synchronized(archive) { ... }` in `ComicDocuments.kt` (same pattern as `synchronized(renderer)` already used for `PdfRenderer` in `BookSession.Pdf`). Reran the same concurrency test after the fix: all 25 pages of the real file decoded correctly under 4-thread concurrent load. |
